## 一、🔴 P0：干净环境无法 Sync（实测确认）

**位置**：`settings.gradle.kts:13`

```kotlin
plugins {
    id("org.gradle.toolchains.foojay-resolver-convention") version "1.0.0"
}
```

`pluginManagement` 只声明了阿里云镜像 + Chaquopy 源，但该插件在阿里云仓库不存在：

| 源 | HTTP 状态 |
|---|---|
| `maven.aliyun.com/repository/gradle-plugin` | **404** |
| `plugins.gradle.org/m2`（官方） | **200** |

**现象**：清空 Gradle 缓存后 Sync 直接失败
`Plugin [id: 'org.gradle.toolchains.foojay-resolver-convention', version: '1.0.0'] was not found`
（本机 Android Studio 能编过，仅因为本地缓存里已有该插件。）

**修复（二选一）**：
1. `pluginManagement { repositories { ... gradlePluginPortal() } }` 补官方源；
2. 直接删掉这个 `plugins {}` 块 —— 本工程已用 `gradle.properties` 的 `org.gradle.java.home=D:/code/app/Studio/jbr` 显式指定 JDK，foojay toolchain 自动下载解析器**本就不需要**。

## 二、🟠 P1：数据库版本与迁移链不自洽

**位置**：`app/src/main/java/.../data/local/AppDatabase.kt:341-566`

- `@Database(version = 13)`，但 `addMigrations(...)` 里注册了 **`MIGRATION_13_14`**（13→14）。
- 数据库停在 v13 ⇒ **该迁移永远不会被触发**，是死迁移。
- 而 `BookDao` 的注释多处写着「命中 v14 新增的 `index_books_savedDir` / `index_books_favorite` / `index_books_finished`」，与 `version = 13` 矛盾。

**实际影响**：轻量版是全新包名、全新库文件，v13 建库时 `@Entity(indices=...)` 已声明这三个索引 ⇒ **索引确实会创建，性能没问题、不会崩溃**。问题是「账实不符」，将来升版本时容易误判。

**修复**：把 `version` 提到 `14`（与完整版对齐），或删掉 `MIGRATION_13_14` 并修正 DAO 注释。

**顺带确认**：`MIGRATION_2_3` ~ `MIGRATION_12_13` 全部是 ADD COLUMN / CREATE TABLE，未使用 `fallbackToDestructiveMigration()` —— 符合「永不丢数据」铁律。✅

## 三、🟠 P1：首启自检的版本修正点沿用了完整版版本号

**位置**：`data/repository/JmRepository.kt:456-462`

```kotlin
VersionFixup(
    appliesFrom = 146,          // ← 完整版 versionCode，轻量版是 1
    summary = "补齐配置默认值",
    run = { repo -> repo.initConfigDefaults() }
)
```

判定条件是 `appliesFrom > fromVersion`，轻量版 `VERSION_CODE = 1` ⇒ 每次版本升级（1→2、2→3…）都会命中这个「从 146 起生效」的修正点，语义完全错位。

**实际影响**：修正点是幂等的 `initConfigDefaults()`，**无破坏性**，但语义错误需修正。改为 `appliesFrom = 1`，或直接删除该条（全新 App 本就无历史数据要补）。

## 七、构建环境备注（非代码问题）

本机 CLI 编译 Gradle 9.7.1 时，`caches/9.7.1/transforms/.internal/locks/*.lock` 反复出现「拒绝访问」（连续 3 次失败）。处理方式：

```bash
./gradlew --stop
rm -rf <GRADLE_USER_HOME>/caches/9.7.1/transforms/.internal/locks
```

清理后重跑即通过（耗时约 6 分钟）。另需确保 `TEMP`/`TMP` 指向**已存在**的目录，否则 Gradle 启动阶段就报
`java.io.tmpdir is set to a directory that doesn't exist`。
