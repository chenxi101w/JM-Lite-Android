# 优化方案（2026-10-14 · 基于 v1.9.0 / versionCode 67）

> 定位：手机版主干的下一阶段路线图。经全量版（jmcomicreader-android v7.8.3）对照与
> 代码实测后制定。原则：**网络层不动**（域轮换/超时/watchdog/恢复已是完整体），
> 集中补「后台体验、功能移植、死代码」三块。

## 零、现状判定（实测确认，不重复造轮子）

**已经是完整体、不动的**：
- 下载队列 v2.0：显式 FIFO（`pending`）+ 可取消 Job（`active`）+ 单调度器，
  Semaphore 泄漏问题已在 v2.0 根治（注释含完整机理分析）
- 双并发档位：`book_download_concurrency` / 图片并发，运行时可调
- API 线路容灾：`JmApiHost` 多源发现 + failover + TLS 坏线排除（v1.2.8 实测）
- API 超时：connect 8s / read 15s（无全量版"API 无超时挂死"问题）
- 图片域：6 域列表 + 逐域重试 + 慢域惩罚演进（v1.8.7）
- 启动恢复（resumePendingDownloads，v1.6.7 首帧延迟版）、watchdog 续下、断点续传
- gradle 镜像 P0 已修（gradlePluginPortal）、DB version=14 账实已对齐

**三大缺口**（本方案主体）：
1. 下载零通知、无后台保活——App 切后台/被杀，下载中断且不可见
2. 全量版 v6.0.7→v7.8.3 的高价值功能未移植
3. 死代码（全量版残留 + 检查报告遗留项）

---

## 一、P0：下载通知 + 前台保活（体验核心）

### 1.1 新增 `DownloadNotifier`（通知发布器）
- 每本独立进度通知：章级（第 X/Y 章）+ 图片级（N/M 张）进度条，标题=书名
- 汇总通知：正在下载 N 本
- 终态通知：完成（✓）/ 失败（含错误信息），完成后自动撤销
- 通道：`IMPORTANCE_LOW`（静默，不吵）

### 1.2 新增 `DownloadService`（前台保活壳，薄）
- **只负责保活与生命周期，不承载下载逻辑**（下载仍归 DownloadManager——队列 v2.0 不动）
- 队列非空 → `startForeground`（汇总通知，`FOREGROUND_SERVICE_TYPE_DATA_SYNC`）；
  队列空 → `stopSelf`
- 进程保活效果：切到桌面/其它 App 下载继续，系统不再轻易杀进程

### 1.3 接线
- `DownloadManager` 暴露进度回调（已有 ch_state/进度流，加一个 notifier 挂点）
- `JmComicApplication` 启动 Service；下载入队/清空时同步 Service 状态
- 权限：`POST_NOTIFICATIONS`（13+ 运行时申请）+ `FOREGROUND_SERVICE_DATA_SYNC`

### 验收
- 发起下载 → 通知栏出现每本进度通知，切桌面下载继续
- 全部完成 → 通知消失；杀进程 → 重启后恢复队列（既有 resume 兜底）

## 二、P1：阅读体验补强（阅读优化 doc 遗留项）

1. **预加载相邻页**：当前页渲染时预取前后各 1 页到内存缓存（防翻页白屏）
2. **Coil 降采样**：阅读大图按屏幕尺寸降采样解码（防 OOM，中端机实测收益大）
3. （可选）章节末尾滑动进入下一章的连贯性手势——单独评审再做

## 三、P2：功能移植（全量版 → 轻量版，按用户价值排序）

| 序 | 功能 | 来源版本 | 移植成本 | 说明 |
|---|---|---|---|---|
| 1 | **回收站**（看完自动进 + 7 天恢复 + 手动删除进回收站） | v7.1.0–v7.1.3 | 中（RecycleManager + Screen + 状态位适配） | 高频刚需，配合轻量版现有"看完标记" |
| 2 | **搜索偏好收藏**（长按收藏词 + 回收站） | v7.4.0 | 中（search_favorites 表 v14→v15 + chips UI） | 高频 |
| 3 | 订阅更新检查（Worker 12h + 发现页区块） | v7.2.0 | 中 | 依赖作者订阅体系（轻量版未移植订阅，需一起） |
| 4 | 连排阅读开关 + 双指缩放（对齐全量版 v7.5.0 语义） | v7.5.0 | 小 | 轻量版阅读器已是自己的实现，需按其架构适配 |

## 四、P3：死代码清理（收尾做）

- 全量版残留链路：订阅残留（检查报告点名）、首页推荐残留等——
  以「功能移植完成后的剩余部分」为准一次清掉（避免清了又加回来）
- `jmreader.data.log.DownloadEventLog` 与全量版日志体系的归并评估

- 包名迁移（jmcomicreader → jmreader）——applicationId 已是 jmreader，
  代码包名迁移纯机械风险无收益，不做
