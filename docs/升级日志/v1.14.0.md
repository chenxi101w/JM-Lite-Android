# v1.14.0 — 章内相邻页预载

> 阅读优化清单（2026-09-29）遗留项收尾：预加载相邻页。
> （Coil 降采样检查结论：**已天然具备**——全局 `RGB_565` + Compose 约束尺寸下
> Coil 自动按目标尺寸解码；`fileImageRequest` 的缓存键策略也已在位，无需重复实现。）

## 是什么

翻到第 N 页时，把 **N+1 / N+2** 页提前 enqueue 进 Coil 内存缓存（复用
`fileImageRequest` 的 lastModified 缓存键，与渲染请求命中同一个 key）。

## 为什么

LazyColumn 只保证「滚动时组合出下一页」，**不保证解码时机**——解码（几十 ms/张，
RGB_565 下也要十几 ms）落在滚动帧上就是可感知的掉帧。预载后翻页直接命中内存
缓存，解码成本移到阅读间隙。

## 实现

- `ReaderScreen` 既有 `snapshotFlow { firstVisibleItemIndex }`（原本只做章末预热）
  扩展为同时预载章内相邻页；
- 与 v1.2.3 的「章末预热下一章前 3 张」共存：章内靠预载、跨章靠预热，无缝衔接。

## 验证

- 编译 BUILD SUCCESSFUL。
- 真机（待验证）：逐页翻阅应无解码卡顿；内存缓存命中（Coil debug 日志 MEMORY）。
