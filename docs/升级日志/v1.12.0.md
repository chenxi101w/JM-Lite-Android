# v1.12.0 · 数据层单表重构（comics）

> 版本号 1.12.0 / versionCode 71 / DB schema v13 → v14
> 日期 2026-10-08

## 一句话

`books + comic_status + read_progress` 三表合一为 **`comics` 单表**——一行 = 一本「看过的」漫画，
状态全部列化，位掩码退役，唯一写入点收敛到 `ComicLedger`，数据漂移从根上消灭。

## 背景

v1.11.0 批量删除 + 云同步暴露数据链路混乱：finished/favorite/viewCount 在 books 与
comic_status 位掩码**双写**、downloadedEver legacy 列、read_progress 独立表、启动体检反复补漂移
（250 号六种记录口径事件）。用户定稿心智模型（2026-10-08）：

- 「看过的」做最大类：收藏 / 看完 / 拉黑都在其中；
- 「下载过」删掉分类维度，降级为物理状态（localDir）；
- 「没看完」= 看完的补集，无需标记列；
- 一次性修复脏数据（迁移 SQL 取大并回），固化判定条件防复发。

## 迁移（MIGRATION_13_14，Room 表重建模式）

1. 建 `comics` 新表（17 列 + `index_comics_localDir` 索引 + `index_search_history_type_content` 补齐）；
2. books 全量迁入（savedDir→localDir，finished/favorite 直搬，blocked=0）；
3. comic_status 实质号（`status & 15 != 0`，BIT_LOCAL=1/FINISHED=2/DOWNLOADED=4/FAVORITE=8）
   无 books 行的补建行（元数据取账本，localDir=''；仅拉黑未看过的丢弃）；
4. 有账本行的 finished/favorite/blocked/viewCount/lastReadAt **五列并回取 MAX**
   （IFNULL 包裹防 NULL 传染违反 NOT NULL）；
5. read_progress 并入进度三列（有行 UPDATE / 无行 INSERT 补建，updatedAt → lastReadAt）；
6. 单章漫画清出 chapters（唯一行且章节 id == bookId = 单行本特征）；
7. DROP 旧三表。目标行集 ≈61~64（旧实质号 61 ∪ books 26 ∪ read_progress 补建 23 去重）。

> 迁移前 adb 备份 `jmcomic.db`；迁移后 run-as 核对行数（见真机验证清单）。

## 新语义

| 概念 | 判定 |
|---|---|
| 看过 | comics 行存在（打开详情/阅读器/下载/收藏/拉黑/同步拉回任一） |
| 在本地 | `localDir` 非空（Kotlin 字段仍叫 savedDir，列名 localDir） |
| 已看完 | `finished = 1`（没看完 = 补集） |
| 收藏 | `favorite = 1` |
| 拉黑 | `blocked = 1` + blacklists（作者级） |
| 已读（进过阅读器） | `viewCount > 0 OR lastReadAt > 0` |
| 曾下载过（已删） | downloads 表仍有记录（removeBook 不删下载记录） |
| 回收站中 | `recycleAt > 0 OR trashed = 1`（原 comic_status.ext JSON 列化） |

## 代码变更

- **Entities.kt**：Book 重写为 comics 单表（+recycleAt/trashed 两列承接回收站标记）；
  删 ComicStatus / ReadProgress 实体；Chapter 注释更新（只存多章）。
- **AppDatabase.kt**：version 14；删 ComicStatusDao / ReadProgressDao；BookDao 新增 7 个定向
  UPDATE + getAll / observeTrashedRows / getReadBookIds / deleteLedgerOnlyRows / clearReadingMemory；
  MIGRATION_13_14（原「索引专项」未发布执行，改写为单表迁移）。
- **BookStatusStore.kt → ComicLedger**（唯一写入点）：ensureRow / setFinished / setFavorite /
  setBlocked / syncBlockedForAuthor / deleteRow / clearReadingProfile；体检退役。
- **BookLibrary.kt**：removeBook 系列改「删本地不清行」；removeBookCompletely 额外清阅读记忆 +
  回收站标记（修复旧版「彻底删除后回收站条目仍挂」的隐患）；进度/看完/收藏全部列写。
- **RecycleManager.kt**：ext JSON 全删，recycleAt/trashed 列读写；回收站流 SQL 直推。
- **BookAutoDeleteManager / DownloadManager**：清位改清 localDir；onDownloaded 退役
  （下载完成 = upsert localDir，行即状态）。
- **JmSyncManager.kt**：PUSH_MASK 删除，push = comics 全表 id（行即「看过」，口径天然一致）。
- **BookTagEngine**：「标签已录入」以 tags 非空判定（TAGS_RECORDED 位退役）。
- **UI 层**：DownloadsViewModel（statuses 流删除）、LibraryViewModel / ReaderViewModel
  （进度字段 lastChapterId/lastPageIndex、曾下载判定改下载记录）。
- **单章漫画**：单行本（photoId≡bookId）不入 chapters 表；下载/详情路径跳过落库并清历史行；
  rebuildChaptersFromLocal 单章 id 用 bookId 对齐路由，目录名显示「全一话」。

## 风险与验证

## 补丁：单章残留清理（装机当日热修，未 bump 版本）

迁移第 6 步的清理条件（`COUNT(*)=1 AND MIN(id)=bookId`）是**新约定形态**，匹配不上旧数据：
旧版单行本按 `id=sort=1` 落库，真机上 23 本单行本全部残留（第 6 步实际删 0 行）。

残留危害：离线详情（getLocalDetail）读到残留行返回旧「第 1 话」（id=1），
而迁移后进度 chapterId=bookId → 离线时进度匹配不上章节。

处理：
1. adb SQL 立即清理（`COUNT(*)=1 AND MIN(id)<>bookId` → 删 23 行，两本多章书 19/43 行完好）；
   删后离线打开自动触发 rebuildChaptersFromLocal 按「全一话」（id=bookId）重建。
2. App 端兜底：`ChapterDao.deleteLegacySingleChapterRows()` + BookLibrary.purgeSingleChapterLegacyRows()
   + JmRepository versionFixups 登记（appliesFrom=71，幂等，防其他设备/回档场景）。
   编译通过后覆盖装机（versionCode 仍 71，schema 未动），进程存活。
