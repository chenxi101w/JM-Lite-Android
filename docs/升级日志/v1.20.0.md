# v1.20.0 — 关于页图标改成「360° 转台 + 反光 + 倒影」

**版本号**：versionName 1.20.0 / versionCode 84
**日期**：2026-10-15
**DB**：无 schema 变更
**性质**：动效（MINOR）

> 用户：「让这个图标跟人家的一样会旋转并且还要有反光」。

## 一、先复述那条硬约束

**桌面启动图标是静态资源，旋转不了** —— Android 桌面只接受位图/自适应图标分层，
没有「动图图标」这种能力（只有个别厂商桌面自己做动效，App 控制不了）。
所以「会旋转」只能做成 **App 内展示时旋转**。若真要桌面图标也动，只能走
「准备 N 帧图标 + 声明 N 个 activity-alias + 后台定时切换」的野路子 ——
启动器刷新时机不可控、还费电，**不建议**，本轮没做。

## 二、关于页的图标动效（本轮主体）

原本是 ±16° 轻微摇摆，现在改成完整的**三维转台**（`ui/components/AuroraHero.kt`）：

| 元素 | 做法 |
|---|---|
| **360° 旋转** | 新增 `turn` 相位（7.2s 匀速一圈），`rotationY = turn * 360f`，配 `cameraDistance` 做真透视。转过 90° 会自然看到镜像面（平面卡片转台的真实观感） |
| **反光** | 高光带位置**与转动同相**（`turn * 2`）—— 就像一束固定光源扫过转动的表面，而不是自顾自地飘；已提到 5 档色阶，中心最亮 0.52 |
| **底部倒影** | 同图标再画一份 `scaleY = -1f`，用 `drawWithContent` + `BlendMode.DstIn` 加垂直渐变遮罩**向下渐隐**，看起来像立在镜面上 |
| **接触阴影** | 椭圆阴影宽度随 `|cos(转动角)|` 变化 —— 侧过去时变窄。**这是让人眼读出「真的在三维里转」的关键线索**，没有它只会像平面在缩放 |
| 常态俯角 | `rotationX = 6°` 固定，避免纯平面的呆板感 |

### ⚠️ 性能（改这个组件前必读）

所有相位（`turn` / `flow` / `spin` / `bob`）**只在绘制阶段读取**
（`Canvas` 的 draw lambda、`graphicsLayer` 的 lambda、`drawWithContent` 的 lambda），
每帧只让 **draw 阶段失效** —— 不重组、不 measure/layout。
**千万不要把相位读进 @Composable 作用域**（例如 `val a = turn.value` 提到外面），
那会让整张卡每帧重组，中低端机立刻掉帧。
