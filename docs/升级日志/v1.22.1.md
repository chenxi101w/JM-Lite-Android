## 一、通读后的发现：人家的流畅是「克制」出来的

对全仓库做动画 API 用量统计：

| API | 人家 | 我们 |
|---|---|---|
| `rememberInfiniteTransition` | **1**（仅关于页色块背景） | 2 |
| `animateFloatAsState` | **0** | 1 |
| `AnimatedContent` | **0** | 1 |
| `graphicsLayer` | **0** | 1 |
| `animateItem` / `animateContentSize` / 共享元素 / `updateTransition` | **全 0** | 全 0 |

→ **人家 47 个文件里只有一处用了动画**。它的流畅 = ①push/pop 转场 ②Tab 瞬时切换
③**其它地方几乎什么都不动**。而且**旋转的 3D 模型跑在 WebView 里、不占 Compose 的帧预算**
（这是它敢于在关于页放动画却依然流畅的原因）。

## 二、找到的最后一个动画来源：M3 的 NavigationBar

我们用的是 Material3 `NavigationBar`，它**每次点击都会跑两段动画**：
1. 选中指示器（胶囊）的缩放/淡入（约 300ms spring）；
2. Material 涟漪。

所以 v1.22.0 把页面切换设成瞬时候，**底部栏自己还在动** —— 用户感知的「不跟手」最后就落在这里。

人家用的是**自己写的 52dp 紧凑栏**（`CompactBottomBar`），
`clickable(interactionSource = remember { MutableInteractionSource() }, indication = null)`
—— **涟漪也关掉**，选中态只靠三件事表达：
**tint 变色 + 字重加粗（SemiBold）+ 图标实心/线性互换**（所以连指示器都不需要）。

## 三、本轮改动

1. `MainScaffold.kt`：`NavigationBar` → 自绘极简栏（52dp + `windowInsetsPadding(navigationBars)`、
   icon 22dp、文字 12sp），`indication = null` 关涟漪，导航逻辑保持
   `popUpTo(起始目的地){saveState} + launchSingleTop + restoreState` 不变。
2. `Navigation.kt`：`TopLevelRoute` 枚举加 `iconIdle`（未选中态线性图标），
   三个 Tab 都配了 Outlined 版本 —— 这是「无指示器也能看出选中」的关键。
3. 保留我们自己的特色：每个 Tab 的**专属选中色**（书架橙 / 搜索青 / 设置紫）。

**副作用（需真机确认）**：关涟漪后，点击底部栏**没有水波反馈**了 —— 这是 iOS 的做法，
也是参考实现的做法，但和 Android 的习惯不同。若觉得少了反馈，把 `indication = null`
换回默认即可（一行）。
