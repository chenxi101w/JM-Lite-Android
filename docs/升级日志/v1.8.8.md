# v1.8.8 — 下载速度回归「每秒真实值」，去掉滑动窗口与平滑

> 用户原话：「**下载速度别搞滑动了，自己骗自己，搞成 1s 测试一次**」。

## 为什么改

v1.8.3 我为了解决「速度读数跳动」，把速度算法从
「上一帧 500ms 差值」改成了「**4 秒滑动窗口 + 指数平滑(0.55/0.45)**」。

读数确实变好看了 —— 但那是**修饰过的数字**，不是当下真实吞吐：

| 场景 | 平滑后的显示 | 实际发生的事 |
|---|---|---|
| 网络卡顿 2 秒 | 还显示几十 KB/s（窗口里存着停顿前的样本） | **一个字节都没进** |
| 停顿结束瞬间 | 从高位缓慢衰减 | 早已停了两秒，看着却像"正在下" |
| 突发低速 | 被 4 秒窗口的高位拉高 | 实际只有十分之一 |

结论：这类数字**没法用来判断问题**，只是好看。
用户要的是能直接看出"这一刻到底有没有在动"的数字，所以改回最朴素的定义。

## 新算法

```
采样周期 = 1 秒（init 里的 delay(1000)）
speed    = (本次 bytes - 上次 bytes) / (本次时刻 - 上次时刻)
```

三条原则：

1. **1 秒采样一次** —— 与进度文件「每秒节流写一次盘」的频率对齐，差值恰好覆盖一次写入，不漏采样；
2. **这一秒字节数没变 → 就显示 `0 B/s`** —— **不沿用上一次的数**，那才是骗人；
3. **跨度用实测时间差**，不假设正好 1.0 秒 —— 读盘与写盘有相位差，
   UI 卡顿也可能让实际间隔 > 1 秒，用实测值算出来的速率才是真的；
   间隔 < 0.5 秒（首帧 / 连续两次几乎同时）时本次不计。

## 代码

`DownloadsViewModel`：

- 删除 `_speedHist`（ArrayDeque 滑动窗口）与 `_speedSmooth`（指数平滑值）两个字段；
- 改为 `_speedPrev: HashMap<Int, Pair<Long, Long>>`（albumId → 上次采样时刻 + 上次字节数）；
- 采样循环 `delay(500)` → **`delay(1000)`**；
- 各分支（DONE / FAILED / CANCELLED / NOT_FOUND / 进度文件过期）统一 `_speedPrev.remove(bookId)`，
  避免残留上一轮的采样点导致下次读到跨阶段的巨大差值。

`formatSpeed()` 未改 —— `speed <= 0f` 本来就返回 `"0 B/s"`，正好符合"停就是 0"的语义。

## 影响范围

`formatSpeed` 还被 `DetailScreen`（图片加载速度）复用，两处现在都是真实值。
