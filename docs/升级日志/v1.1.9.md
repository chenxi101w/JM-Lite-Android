## 一、底部导航：压缩上方留白

### 根因

不是我们额外加的间距，而是 **M3 `NavigationBar` 的固定内部布局**：

- `NavigationBarItem` 内部高度**固定 80dp**，其内容（indicator 32dp + 间距 + label）**垂直居中**于这 80dp；
- 外层容器此前已压到 68dp，于是内容落在容器的 **14 ~ 66dp** ——
  **顶部白留约 14dp**，这就是用户看到的「导航键上面留白太多」。

### 改动（`MainScaffold.kt`）

```kotlin
NavigationBar(
    modifier = Modifier
        .height(60.dp)      // 68 → 60dp
        .offset(y = (-10).dp),   // 整体上移 10dp
    ...
)
```

上移后内容约落在 **4 ~ 56dp**，上方只余一点白。

配套说明：导航栏背景色画在**外层 Box** 上（未被 offset 影响），所以上移不会在底部露出断层。

## 二、顶部搜索框：去掉小字 + 压缩高度

### 改动（`SearchScreen.kt`）

| 项 | 原 | 现 |
|---|---|---|
| 提示文字 | `label`（浮动标签「搜索关键词（标题 / 标签）」）—— 常驻占位、视觉厚重 | **`placeholder`**（「搜索关键词」，输入后自动消失） |
| 高度 | M3 默认（约 56dp，含 label 空间） | **52dp** |
| 形状 | 默认圆角 | **胶囊圆角 26dp** |
| 图标 | 默认尺寸 | 20dp（略收） |
| 文字 | 默认 | `bodyMedium` |

配合 `DiscoverScreen` 的 `PaddingValues(top = 2.dp)`（v1.1.7 已改），顶部整体更紧凑。

### 附带发现：耗时记录里「回退」次数偏高

关于页统计显示：JSON 接口 14 次（均 1437ms）、Python 链路 7 次（均 3920ms）、
**接口失败回退 46 次**。

该记录**跨版本累积**（SharedPreferences 持久化），46 次回退主要来自 **v1.1.5 之前**——
那时「纯数字 JM 号搜索」必然回退（`redirect_aid` 尚未适配），而用户恰好常用 JM 号搜索。

**建议**：在关于页点「清空」，之后重新积累，即可看到修复后的真实分布。

另注：编码上限为 3 位 base36 = **46655ms（46.6 秒）**，统计里「最慢 46655ms」即触顶截断值
（真实值可能更大，多为 Python 冷启动或超时重试）。极端慢样本会被截断，属已知限制。
