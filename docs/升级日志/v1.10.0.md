# v1.10.0 — 云同步：看过的漫画 JM 号备份到自有服务器

> 用户：「这是我的服务器，你以后可以用它保存我们的看过的漫画的 jm 号，然后跟手机 App 同步。」

## 是什么

设置 → 书架 → **云同步**。开启后，把本地「看过的漫画」账本（`comic_status` 全集的 JM 号）与用户自己的阿里云 ECS 双向合并：

- **换机 / 重装 / 清数据**后开启同步 → 服务器账本拉回本地，一键找回全部看过的 JM 号。
- 服务器**只存数字 ID + 时间戳**，不存任何书名/标签/文本（隐私最小化，服务器被看也只看到一堆数字）。

## 服务器端（已部署并验证）

- 阿里云 ECS `your-server`（Ubuntu 22.04，2C2G），`/opt/jm-sync/server.py`，纯 Python 标准库（http.server + sqlite3），systemd 托管 `jm-sync.service`（Restart=always）。
- 数据库 `/opt/jm-sync/history.db`：`history(jm_id PK, added_at, last_read_at)`。
- 接口（token 常量比较鉴权，访问日志静默）：
  - `GET /pull?token=T` → `{"count":N,"detail":[{id,added_at,last_read_at}...]}`
  - `POST /push?token=T` body `{"ids":[...]}` → `{"ok":true,"received":N,"new":M}`（INSERT OR IGNORE 幂等）
- 公网验证（2026-10-08，安全组放行 8765 后）：pull 200 / push new=1 / 重复 push new=0（幂等）/ 错 token 403，五项全过；测试数据已清理，账本归零待首同步。
- 密钥：存放于 `.workbuddy/tmp/jm_sync/credentials.txt`（不入库；铁律：密钥不写进任何文档）。

## 合并语义（本地为权威）

- **入**：服务器有、本地无 → `comic_status` 落一张空状态行（只有 bookId + lastReadAt，title/cover 留空）。本地已有的行**绝不动**（不被覆盖、不清位）。
- **出**：本地全集全量 push（服务器幂等，重复 push 无副作用）。
- 拉回的号要看哪本，直接搜 JM 号进详情，元数据自然落库。
- 只有**成功同步**才写 `sync_last_at`（自动同步的节流依据）；手动「立即同步」不受节流限制。
