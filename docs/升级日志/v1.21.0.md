## 一、人家的实现（扒完的结论）

### 1) 那个「3D 渐变」= 模糊色块漂移背景（Compose 画的）

`AboutScreen.kt` 里的 `AnimatedBlobBackground()`：

| 参数 | 取值 |
|---|---|
| 颜色 | 12 色调色板（紫/紫罗兰/靛蓝/蓝/青/青绿/绿/黄/橙/红/粉/紫红）**随机取 3 个** |
| 色块形状 | 圆形，径向渐变 `[实色, 同色 30% 透明, 全透明]` |
| 尺寸 | 1020dp / 880dp / 500dp（**巨大**，所以只看到柔光，看不到圆） |
| 位移 | 6 个独立相位：X/Y 各一，周期 8/10/12/9/11/13 秒，`FastOutSlowIn`、`RepeatMode.Reverse` |
| 整体 | 容器套 `Modifier.blur(80.dp)` |

→ 所以它不是静态渐变、也不是我原来那套「旋转极光 + 陀螺光环」，而是**慢慢流动的柔光**。
本轮已 1:1 照搬（尺寸按我们卡片缩小、`blur(60.dp)`、深色主题下压到 0.7 亮度防荧光）。

### 2) 那个「3D 物体」= WebView + `<model-viewer>` + 真 GLB 模型

- `assets/about_model.html`：Google 的 `<model-viewer>` 组件，加载 **`assets/models/JM.glb`**；
- 关键属性：`auto-rotate`、**`rotation-per-second="20deg"`**（一圈 **18 秒**）、
  `camera-orbit="0deg 95deg 200%"`（俯视 95°）、`exposure="1.2"`、`shadow-intensity="0"`、
  `disable-zoom`、透明背景；
- `AboutModelPreloader`：**WebView 预加载 + `window.__modelReady` 就绪标记**，做到进页面秒开；
- 布局：屏幕高度上 1/3 给模型区（固定高度，避免 WebView 在 weight 布局里高度为 0）。

→ 它好看的根本原因是**这是一个真的三维模型**：转动时能看到书脊、厚度、页缘，
以及 PBR 材质在默认环境贴图下的**真实反射**。

## 二、本轮改了什么

1. **背景换成模糊色块漂移**（照搬参数，尺寸按卡片缩小）；
2. **转速对齐 20°/秒**；
3. 保留 v1.20.0 的反光 / 倒影 / 接触阴影（人家没有这三样，但它们让「反光」更明显，
   是用户明确要的）；
4. 文案与药丸改用主题色 —— 背景从「深紫卡」变回主题表面色后，原来的白字会看不见。

## 三、要完全一样，还差一个 GLB（待用户决定）

| 方案 | 做法 | 代价 |
|---|---|---|
| **A. 照搬 GLB + model-viewer** | 内置 `model-viewer.min.js`（~1MB）+ 一个 GLB + WebView 预加载 | **+约 1.2~2MB 体积**（与我们连做 5 版「轻量化」的方向相反）；需先有 3D 模型 |
| ├ A1. 程序生成 GLB | 用 Python 写一个**厚板挤出模型**：正面贴我们的图标贴图 + 侧面纯色边 + 背面，UV 手工排 | 极小（几十 KB），**图标细节 100% 保留**，真实光照/反射；不是「书本模型」而是「厚卡模型」 |
| ├ A2. AI 生成 3D 模型 | 用多模态 3D 生成从图标图出 GLB | 需消耗生成额度，且**扁平卡通风转 3D 极易丢细节**（用户已因此否过一次） |
| **B. 保持现状（平面旋转）** | 无新资源 | 转到侧面会露出「一条线」的平面感，**永远达不到人家的体积感** |
| **C. 折中：手绘伪厚度** | Compose 里额外画一个「侧面」色带，随 `sin(θ)` 变化宽度 | 无资源、能缓解「一条线」的突兀，但终究是 2.5D |

**建议**：若用户接受 +1MB 左右，走 **A1**（程序生成厚板 GLB）——它是唯一能同时做到
「真三维体积 + 真反射」且**不丢图标任何细节**的路径。若坚持轻量，保持 B/C。
