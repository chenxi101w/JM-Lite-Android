## 一、进度动画（核心）

### 问题

`LinearProgressIndicator` 的进度值直接取自轮询结果：

```kotlin
progress = { (progress.done.toFloat() / progress.total).coerceIn(0f, 1f) }
```

而**进度是每 500ms 轮询一次**（不调 Python，只读进度文件）——每次采样直接赋值，
进度条就是**一格一格地跳**，视觉上是阶梯式跳动，没有"在走"的连续感。

### 修复：补间动画衔接轮询节奏

```kotlin
val targetFraction = when {
    dl.status == "DONE" -> 1f
    progress != null && progress.total > 0 ->
        (progress.done.toFloat() / progress.total).coerceIn(0f, 1f)
    else -> 0f
}
val fraction by animateFloatAsState(
    targetValue = targetFraction,
    animationSpec = tween(durationMillis = 550, easing = LinearEasing),  // 略长于轮询间隔
    label = "download-progress"
)
```

**关键取舍**：动画时长 **550ms 略长于轮询间隔 500ms** —— 使相邻两次采样首尾相接，
进度条持续匀速推进而不是逐格停顿。缓动用 `LinearEasing`（匀速），与"下载"这一匀速语义一致。

## 二、卡片 UI 重构

### 布局对比

| 原来 | 现在 |
|---|---|
| 标题 → 提示文字 → **状态文字** → 进度条 → **进度文字**（信息分散在 4~5 行） | 标题 → **状态行（合并）** → **进度条 + 百分比** |
| 进度信息只对 `DOWNLOADING` 显示，且与状态文字分两行重复 | 状态 + 图片数 + 速度合并一行；百分比挂在进度条右侧 |
| `DONE` 无进度条（视觉上"没有闭环"） | **`DONE` 也显示满格进度条**，状态色区分 |
| 进度条默认高度/配色 | **6dp 高 + 圆角 + 状态色 + 圆头线帽** |

### 状态配色

| 状态 | 进度条颜色 |
|---|---|
| `DOWNLOADING` | `primary`（主色） |
| `DONE` | `tertiary` |
| `FAILED` | `error` |
| `QUEUED` | `outline` |

轨道色统一 `surfaceVariant.copy(alpha = 0.45f)`，保证浅/深色主题下都有足够对比。

### 其他细节

- 卡片内边距改为 `start=14, end=6, top=10, bottom=12` —— 右侧留给按钮，视觉更透气；
- 操作按钮（⟳ / ✕）尺寸 38dp、图标 19dp，比默认略收敛，与紧凑布局匹配；
- 警示文字（"已不在本地"、"已拉黑"）间距同步微调。
