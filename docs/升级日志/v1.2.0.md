# JM 轻量版 v1.2.0 升级日志

**版本号**：versionName 1.2.0 / versionCode 15
**日期**：2026-10-01
**DB**：沿用 v13（无 schema 变更）
**包名**：`com.example.jmreader`

## 版本说明

修掉「阅读时往后拉会被拉回来」的滚动 bug（**v1.1.2 留白修复引入的副作用**），
并处理搜索页「一进去就转圈」的问题、美化加载动画。

---

## 一、🔴 阅读滚动被拉回（核心修复）

### 现象

用户反馈：阅读时往后拉（向下滚动看后面的页），**位置会被拽回去**。

### 根因（v1.1.2 引入）

v1.1.2 为消除留白，改为按图片真实宽高比布局，比例取自 `painter.intrinsicSize`：

```kotlin
val painter = rememberAsyncImagePainter(model = File(p))
val ratio = if (sz.isSpecified && ...) sz.width / sz.height else DEFAULT_PAGE_RATIO
Image(..., modifier = Modifier.aspectRatio(ratio))
```

问题在于 **图片加载完成前后比例不同**：

| 时刻 | ratio | 后果 |
|---|---|---|
| 加载中 | `DEFAULT_PAGE_RATIO` = 0.72（占位） | 列表项高度 H1 |
| 加载完成 | 真实比例，如 0.702 | **列表项高度 H2** |

高度一变，`LazyColumn` 就要重算已测量项的位置 → **用户滚到一半的位置被拽回**。

### 修复：预读图片尺寸，让高度从第一帧就固定

`ReaderViewModel` 新增 `pageRatios`，在**进入章节时**（`loadLocalPaths`，已在 `Dispatchers.IO` 上下文）
用 `BitmapFactory.Options(inJustDecodeBounds = true)` **只读文件头**拿到每页宽高比 —— 不解码像素，单张约 0.1~1ms。

渲染层不再依赖 `painter.intrinsicSize`，直接用预读值：

```kotlin
val ratio = ratios[idx] ?: DEFAULT_PAGE_RATIO
AsyncImage(..., modifier = Modifier.fillMaxWidth().aspectRatio(ratio))
```

占位框也用同一比例 → **加载前后高度完全一致，滚动位置不再被改写**。

顺带收益：
- 不再需要 `rememberAsyncImagePainter` / `Size.isSpecified` 判断（v1.1.3 崩溃的那个坑整个绕开了）；
- 排版首帧即正确，不再有"撑开"过程。

## 二、搜索页「一进去就转圈」

### 根因

`SearchViewModel` 的初始状态就是 `UiState.Loading`，页面按状态渲染时**未搜索也显示转圈**。

### 修复

UI 层用已有的 `searched` 标记区分「还没搜过」与「正在搜」：

- **未搜索过** → 引导空态（淡色放大镜图标 + 「输入关键词开始搜索」）
- **搜索中** → 加载动画
- 已搜索 → 结果 / 错误

---

## 三、加载动画美化（新增 `PrettyLoader`）

`ui/components/PrettyLoader.kt`，替代 M3 默认 `CircularProgressIndicator`：

| 设计点 | 说明 |
|---|---|
| 轨道 + 光弧双层 | 低对比度圆形轨道打底，扫掠光弧在上，有层次而非单根孤弧 |
| 渐变收尾 | 光弧用 `sweepGradient`（透明 → 主题色），末端自然不生硬 |
| 呼吸感 | 旋转**匀速**（1150ms/圈）、弧长**来回摆动**（950ms 往复，0.12↔0.78）—— 两个节奏错开 |
| 圆头线帽 | `StrokeCap.Round`，线条柔和 |

颜色取自 `MaterialTheme.colorScheme.primary`，随主题联动。

## 四、阅读进度滑轨：热区放大 + 支持拖动

### 现象

用户反馈：右边的快速翻页**不好碰到**。

### 根因

滑轨的**触摸热区就是视觉宽度 6dp**（`Modifier.width(6.dp)` 同时决定了外观和可点范围）。
Android 建议的最小触摸目标为 48dp —— 6dp 只有其 1/8，手指几乎不可能精准按住。

同时它**只支持「按下即跳」**（`detectTapGestures(onPress)`），没有拖动跟随。

### 🔍 顺带挖出的真问题：一处死代码导致「隔离重组」从未生效

改这个滑轨时才发现，`ReaderScreen.kt` 里存在**两份实现**：

| 位置 | 状态 |
|---|---|
| `ReaderProgressRail()` 函数（约 682 行） | **从未被调用** —— 死代码 |
| Scaffold content 里的内联 `Box`（约 503 行） | **实际渲染的是这一份** |

而该函数上方的注释写着 v14 的性能修复说明：

> 此前进度值直接在 Scaffold content 里读 `listState.firstVisibleItemIndex`，该读取把「翻一页」
> 变成了整个 content 的重组源 —— 顶栏、LazyColumn、底部按钮、信息卡全部重跑。
> 现在：①抽成独立 Composable 隔离重组范围；②derivedStateOf ……

**也就是说：这个修复当时并未真正落地** —— 函数抽出来了，但调用没接上，
内联版仍在原地直接读 `listState`，翻页依旧触发整个 content 重组。

### 改动

1. **删掉内联实现，改为调用 `ReaderProgressRail()`** —— 一处实现，
   同时让「隔离重组范围」真正生效（进度值由函数内 `derivedStateOf` 自持）；
2. 清理随之失效的外层变量（`railHeight`、`progress`）；
3. **位置：右 → 左**（用户选定）—— 左侧留给进度控制，**右侧完整留给正文滚动**，
   避免手势互相抢占；
4. 热区与交互按下表调整。

| 项 | 原 | 现 |
|---|---|---|
| 触摸热区 | **6dp**（= 视觉宽度） | **28dp**（≈屏宽 2.6%） |
| 视觉宽度 | 6dp | 6dp 不变 → 按住/拖动时**加粗到 10dp** 作反馈 |
| 交互 | 仅点按定位 | **按住即跳 + 拖动实时跟随** |
| 位置 | 右侧 | **左侧** |

实现要点：外层 28dp 容器接管手势，内部再画 6dp 细条 —— **外观纤细、手感宽厚**。

### 取舍说明

滑轨改到左侧后，**左侧 28dp 竖条区域**由滑轨接管（该区域内上下滑动为进度定位，不再滚动正文）；
右侧完全交还正文滚动。若左侧仍觉干扰，把 `width(28.dp)` 调成 `20.dp` 即可（仍远好于 6dp）。
