## 一、关于页：3D 极光展示卡（新增 `ui/components/AuroraHero.kt`）

原先关于页头部只是一个「圆角卡片 + 静态图标 + 名称」——没有任何动感。现在换成一块 196dp 高的展示卡，四层视觉叠加：

| 层 | 效果 | 周期 |
|---|---|---|
| ① 流动极光底 | 多色线性渐变（主题紫系）绕中心旋转 | 14s / 圈 |
| ② 3D 陀螺光环 | 两层 sweep 渐变圆盘垂直压扁（scaleY 0.42 / 0.30）后**反向**自转 → 平面上模拟出立体全息盘 | 9s / 15s |
| ③ 浮动高光 | 柔和径向高光沿椭圆轨道游走（玻璃反射感） | 14s / 圈 |
| ④ 前景图标 | `graphicsLayer` 的 rotationY ±16° + rotationX 4~12° 配 `cameraDistance` → **真实透视翻转**；表面另有镜面扫光 | 5.2s 往复 |

- 颜色全部取自 `MaterialTheme.colorScheme`（primary / tertiary / primaryContainer / secondaryContainer），
  **切主题风格（墨夜/纸感/霓虹/暮紫）时极光会跟着变**，不是写死的一套紫。
- 版本号做成卡内小药丸，下方信息卡的「版本」行改为「版本号（build N）」避免重复。

### ⚠️ 性能约束（改这个组件前必读）

三个动画相位虽然都是 State，但**只在绘制阶段读取**（`Canvas` 的 draw lambda、
`graphicsLayer` 的 lambda 块内），因此每帧只让 **draw 阶段失效** —— 不重组、不 measure/layout。
这是它能在中低端机满帧的关键。**后续改动不要把相位读进 @Composable 作用域**
（例如 `val p = flow.value` 提到外面再用），那会让整张卡每帧重组。

## 二、页面转场：默认值就是卡顿来源

**根因**：`NavHost` 原先**没配任何转场**，走的是 navigation-compose 的默认值 ——
**700ms 纯交叉淡入淡出**。后果有两重：
1. **慢**：点一下要等近 0.7 秒才算到位，主观就是「拖」；
2. **糊/卡**：淡出与淡入两屏**同时合成**，等于每次切换都要多渲染一整屏，冷启动一屏的开销被暴露出来。

**修法**（`ui/Navigation.kt`）：统一改为「淡入 + 轻微缩放」，时长压到 190~240ms：

- enter：`fadeIn(190)` + `scaleIn(0.94 → 1, 240ms, FastOutSlowInEasing)`；
- exit ：`fadeOut(150)` + `scaleOut(1 → 1.03, 190ms)`（让退出的那屏「退到后面去」，不抢焦点）；
- pop 方向同理，位移略小（0.96 起）。
- **阅读器路由单独走纯淡入**（160/140ms）—— 全屏看图时任何位移/缩放都会让人觉得画面在抖。

## 三、顺带查清「都是 20MB」这件事

用户拿我们的体积和别人比。查了实际产物：

| 文件 | 大小 | 说明 |
|---|---|---|
| `JM_v1.16.0_debug.apk`（用户装的） | **19.4 MB**（解压后 64MB，218 个 dex/资源） | **debug 包** |
| 其中 `classes.dex` | 44.2 MB 未压缩 | Kotlin + Compose + material-icons-extended，**未做任何裁剪** |
| 其中 `classes17.dex` | 13.7 MB 未压缩 | 同上 |

**release 已经开了 R8（`isMinifyEnabled = true` + `isShrinkResources = true`）**，而 debug 不做裁剪。
所以「我们 20MB vs 人家 20MB」是**拿我们的 debug 比人家的 release**——不公平，而且说明我们还有大量余量。
本 App 只用了 25 个 Material 图标，其中 9 个必须靠 `material-icons-extended`（CollectionsBookmark /
GridView / TravelExplore / CloudDownload / Tune / StarBorder / Brush / MenuBook / Download）；
release 裁剪后这一整包会被削掉绝大部分。
→ **待办：出一次 release 包实测体积**（未做，等用户发话——按项目规矩不擅自打包）。
