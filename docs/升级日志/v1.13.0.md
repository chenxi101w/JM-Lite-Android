# v1.13.0 — 下载通知 + 前台保活服务

> 用户对照 YOMII（jm-comic-android）后的核心诉求：下载管理要有**通知栏进度**和**后台保活**。
> 架构原则：**队列 v2.0 不动**（FIFO + Job 调度是完整体），新增的服务只做「保活 + 通知」薄壳。

## 是什么

- **每本独立进度通知**：第 X 张图 / 共 N 张的进度条，实时刷新（1s 轮询进度文件，与下载管理页同一真源）。
- **汇总通知（前台服务）**：有活跃下载时进程转前台优先级——切桌面、锁屏、其它 App 都不会被系统轻易回收，下载不中断。
- **结果通知**：完成（✓ 已存入书架）/ 失败（含重试提示），完成后自动撤掉进度通知。
- 通知权限（Android 13+）**只在第一次启动申请一次**，拒绝后不再打扰。

## 实现

| 文件 | 内容 |
|---|---|
| `jmreader/data/download/DownloadNotifier.kt`（新） | 通道管理（进度=低优先级静默 / 结果=默认）+ 通知构造 |
| `jmreader/data/download/DownloadService.kt`（新） | 常驻轮询循环（1s）：活跃下载 → `startForeground(dataSync)` 保活 + 发布通知；终态发布结果通知（`finalNotified` 去重）；队列空 → 退出前台但不停止循环 |
| `JmComicApplication` | 启动即拉起服务（START_STICKY，系统回收后自愈重建） |
| `MainActivity` | POST_NOTIFICATIONS 一次性申请（v1.2.7 移除的权限申请回归——这次通知有真实用途，且只弹一次） |
| `AndroidManifest` | POST_NOTIFICATIONS / FOREGROUND_SERVICE / FOREGROUND_SERVICE_DATA_SYNC + service 声明（dataSync 类型） |

## 设计取舍

- **服务是薄壳，不是下载宿主**：队列 v2.0 的 FIFO/Job/去重/watchdog 全部保留原位，服务只观察
  进度文件真源 + 保活。这样下载语义零变化，服务被回收也不影响下载本体。
- `dataSync` 前台类型在 Android 15 上有 6 小时时限——超时会退出前台保活（下载协程仍在），
  极端长下载靠断点续传 + 启动恢复兜底。
- 权限申请改为一次性（`notif_permission_asked` 标记），修复 v1.2.7 记录的「每次冷启动都弹」骚扰。

## 验证

1. 编译：`compileDebugKotlin` BUILD SUCCESSFUL。
2. 真机（待验证）：① 发起下载 → 通知栏出现每本进度通知 + 汇总通知；② 切桌面/锁屏下载继续；
   ③ 完成后结果通知弹出、进度通知消失；④ 队列清空后前台服务自动退出；⑤ 首启只弹一次通知权限。
