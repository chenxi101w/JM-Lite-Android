## 一、已做：搜索栏随滚动收放

- 内容下滑 → 搜索栏收起；上滑 → 展开（与底部栏/悬浮球同一套方向阈值方案，180ms）。
- **用真实高度动画**（外层 `Box` 裁切 + `Animatable` 驱动高度），不是 `graphicsLayer` 平移 ——
  平移会在收起后留下一块空白高度，看起来像「上面少了一块」。
  网格是 `weight(1f)`，搜索栏收起时自动填满 → 视觉上就是「内容长大一格」。
- **无结果时强制常驻**（没东西可滚，藏起来等于把搜索入口也弄没了）。
- 只认方向、不跟手：6px 阈值过滤惯性滚动与子控件位移。

## 二、分类检索放哪里：我的建议 + 一个必须先解决的硬门槛

### 建议位置：**主页顶部一排横滑分类 chip**（不放独立 Tab）

| 方案 | 评价 |
|---|---|
| **A. 主页顶部横滑分类 chip（推荐）** | 一行能放 5–6 个；点一下直达结果，**复用已有的带参搜索链路**（`SEARCH_ARGS`，详情页点作者/标签就走它）→ **零新页面** |
| B. 独立第 4 个 Tab | 我们底栏已有 3 个 Tab，再加一个每格只剩 ~90dp，图标+文字会挤 |
| C. 主页放「分类」入口 → 九宫格分类页 → 结果 | 多一层跳转，收益不匹配 |

### ⚠️ 硬门槛：**接口不存在，而且能不能免登录用还没验证**

1. 我们的 API 客户端（`JmApiClient`）**只有 `search`**，**没有 `/category`（分类树）、没有 `/list`（分类结果）、也没有 `/recommend`（推荐）**。
2. 我在沙箱里用签名头（`Token = md5(time + APP_TOKEN)`）实测了 `/category` 与 `/recommend`：**全部 404**，
   连**正在使用的 `/search` 也 404** —— 原因是我们用的线路是**动态下发**的
   （`JmApiHost` 从 `newsvr-2025.txt` 解密得到），代码里那三个 `cdn-msp*.jmapiproxy1.cc` 是旧 fallback。
   **所以「这两个接口免登录能不能用」我在沙箱里验证不了，不猜。**
3. 参考实现有 `LoginScreen`（登录页），我们的轻量版**没有账号体系**。JM 的分类/推荐接口通常需要登录态。

### 因此分两步走

- **第一步（已做）**：搜索栏随滚动收放 —— 纯 UI，零接口依赖。
- **第二步（待用户拍板）**：接分类/推荐接口。需要：
  1. 在 `JmApiClient` 加 `/category` + `/list`（或 `/recommend`）；
  2. **在真机上先验证这两个接口免登录是否可用**（我不能替你在真机验证）；
  3. 若必须登录 → 还要加账号体系（那是一个大功能，要单独评估）。
