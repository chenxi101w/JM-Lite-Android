## 版本说明

**修复「已下载的漫画离线看不了」—— 用户实测反馈的可用性 bug。**

用户反馈：「详细页好像要网才能进，害得我看不了漫画。」

---

## 一、根因（三处环环相扣）

```
① 下载从不写 chapters 表
   DownloadManager.downloadAlbumInternal 只写 books(savedDir) + downloads + comic_status
   → 「JM 号直达下载」等未访问过详情页的路径，本地 chapters 表为空
        ↓
② 书架点卡片因此跳「联网详情页」
   LibraryViewModel.openRouteFor：firstChapterId(local=true) 为空 → Routes.detail(id)
   而 Routes.detail 默认 local=false → DetailScreen 强制联网
        ↓
③ 阅读器也依赖 chapters 表
   ReaderViewModel.loadLocalPaths：chapters.firstOrNull { it.id == chapterId }
   → 找不到章节 → 报「本章未下载，请到详情页下载后阅读」
   （实际本地图片就在 savedDir/{sort:03d}/ 里，只是没记录可查）
```

**结论**：本地图片一直在，缺的是「章节登记表」。一旦断网，用户既进不了详情页（要联网），
也进不了阅读器（查不到章节），已下载的漫画等于废了。

---

## 二、修复（四处）

| # | 位置 | 改动 |
|---|---|---|
| 1 | `jm_bridge.py` `download_album` | 下载完成回传 **`chapter_list`**（`id`/`sort`/`name`）—— 此前只回传章节**数量**，Kotlin 无从落库 |
| 2 | `DownloadManager.kt` | 新增 `chapterDao`；下载完成后把 `chapter_list` 写入 `chapters` 表，**并保留已有的 `finished` 已读标记**（重下不清进度） |
| 3 | `BookLibrary.kt` | 新增 `rebuildChaptersFromLocal()`：chapters 表为空但本地有下载目录时，**扫描目录重建章节**并落库；`getLocalDetail()` 与 `getChapters()` 均接入该兜底 |
| 4 | `DetailViewModel.kt` | **本地优先**：已下载直接吃本地数据（含重建章节）不联网；未下载才联网，且**联网失败时回退本地**而非直接报错 |

### 关于「老数据」的处理

第 3 项是关键补充：**此前已经下载过、chapters 为空的漫画，不需要重新下载**。
首次打开时会扫描 `savedDir/*/` 目录（目录约定 `{sort:03d}/{idx:03d}.jpg`），
按数字目录名重建章节列表并落库，之后即可正常离线阅读。

- 章节 `id` 取 `sort` 值（早期数据没有真实 photo id，无从还原）；
  阅读器只用 `id` 匹配章节、用 `sort` 定位目录，**自洽即可**。
- 只统计**含图片文件**的目录，避免半途失败留下的空目录变成假章节。

## 三、修复后的行为

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 新下载（含 JM 号直达下载） | 本地无章节，离线读不了 | 下载即写章节表，离线可读 |
| 书架点已下载漫画 | 跳联网详情页，断网卡死 | 本地直出详情（不联网） |
| 断网进详情页 | 报错 | 有本地数据即正常显示 |
| 历史下载（chapters 为空） | 离线读不了 | 自动从目录重建章节 |
| 重下同一本 | — | 保留原已读标记 |

---

## 四、验证要点

1. **断网**（飞行模式）下：书架点一本已下载漫画 → 能进详情页、能进阅读器、能翻页。
2. 新下载一本（走「JM 号直达下载」，不进详情页）→ 完成后断网，确认可读（验证第 1、2 项修复）。
3. 用一本**修复前就下载过**的漫画 → 断网打开，确认自动重建章节后可读（验证第 3 项）。
4. 重下一本已读过的漫画 → 确认「已读 X/N」标记没被清掉。
