> 用户洞察：「**分类其实就是关键词啊**」——设置里自定义分类关键词（悬疑、萝莉、御姐、巨乳等）。

## 一、为什么这个思路比接接口好

上一轮结论是"分类/推荐接口不存在且可能要登录态"。用户一句话把问题拆穿了：

- **搜"悬疑"出来的结果，和点分类"悬疑"出来的结果，本来就是同一批** → 分类在结果层面**就是关键词**；
- 我们的 `search(keyword)` **已经在用**（免登录可用）→ **零新接口、零门槛**；
- 而且比固定分类表更灵活：**用户想加什么词就加什么**，不用等我们更新。

对照参考实现：它的 `/category` + `/list` 需要登录（它有 `LoginScreen`），我们轻量版没有账号体系 ——
这个方案直接绕开了整条登录链路。

## 二、改动清单（4 个文件）

| 文件 | 改动 |
|---|---|
| `ConfigManager.kt` | 新增配置键 `home_categories`，默认值 `悬疑,萝莉,御姐,巨乳` |
| `SearchViewModel.kt` | 新增 `homeCategories: StateFlow<List<String>>`（走 `observeConfigAll()`，**设置里改完切回主页自动生效**）；顶层函数 `parseCategories()`：逗号/顿号/换行/分号都当分隔符，去空去重保序 |
| `SearchScreen.kt` | 主页搜索框下方加一排横滑 `FilterChip`；点 chip → `setKeyword(cat) + onSearch()` + 收键盘 + 回到结果顶部；已选中的 chip 再点不重复搜 |
| `SettingsGroupScreen.kt` | 「设置 → 搜索」顶部加「分类关键词」多行输入（`CategoryInput`），**600ms 防抖**再落库（逐字写 DB 会把手势打得一顿） |

### 收放区的高度要跟着变

上一轮做的"搜索栏随滚动收放"，盒子高度原本固定 52dp；现在盒子里装了
**搜索框 + 分类 chip 行**，高度改为 `if (分类为空) 52.dp else 98.dp` —— 两个一起收放，
视觉上仍是"顶部区域随滚动让位给内容"。
