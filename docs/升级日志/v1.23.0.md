## 一、详情页切不回书架（根因 + 修法）

**根因**：底部栏是**页面级**的 —— 只有那几个「自己调 `MainScaffold`」的顶级页面才有底栏；
而 `DetailScreen` / `ReaderScreen` 自己画了**全屏 Scaffold**，把外层内容整个盖住。
于是从详情页进搜索等深层页面后，**屏幕上根本没有 Tab 可点**，只能按返回键一层层退。

**修法**（两条一起上，正好对上用户提的两个顾虑）：

1. **底栏抽成可复用组件 `CompactTabBar(currentRoute, nav)`**，详情页的 Scaffold 也挂上
   → 进详情页后可以直接点书架，一步到位（阅读器**仍保持全屏沉浸**，看图不该有栏）。
2. **`DetailViewModel` 从「页面作用域」提升到「NavHost 作用域」**
   （与 `LibraryViewModel` / `SearchViewModel` 一致，`Navigation.kt` 里统一持有再传入）。
   它的 `load()` 本来就有「同一本不重拉」的缓存护栏（`loadedId == albumId` 且仍是成功态则直接返回），
   但**页面作用域的 VM 一离开就销毁 → 缓存白留**。提升之后：
   详情页 → 书架 → 再回同一本 = **直接复用已加载状态，不转圈、不重新请求**。
   （安全性已核对：换书时 `load()` 会先置 `Loading`，收藏/已读等状态在成功后重新赋值，
   旧的章节观察 job 也会先 cancel。）

## 二、悬浮球随内容滚动收拉

`DraggableDownloadFab` 现在会跟随滚动：内容下滑时缩到 0（完全收起），上滑立刻复原。

- **驱动方式**：在 `MainScaffold` 的内容层挂一个 `NestedScrollConnection`，只翻转方向时触发
  `Animatable.animateTo`（180ms）。**不需要给每个页面的列表加代码**。
- **用真实尺寸变化而不是 `graphicsLayer` 缩放**：后者会留下一个透明的 56dp 点击区，
  收起后点那块地方会误进下载页。尺寸变化则连点击区一起消失。
- 6px 阈值过滤掉惯性滚动/子控件的微小位移，避免频繁切换。

> 说明：参考实现里**没有**这个交互（人家全仓库零 `scrollBehavior`，也没有悬浮球），
> 这是按用户要求自己加的。

## 三、美术风格：先做最有把握的一项

对照参考实现量出来的三组数：

| | 人家 | 我们（改前） |
|---|---|---|
| 圆角 | **只用 3 个值**：12 / 10 / 8 dp | 9 个值：26 / 24 / 22 / 18 / 12 / 8 / 5 / 4 / 3 |
| 字号 | **只有 3 档**：22 / 16 / 11 sp | M3 默认 11 档 |
| 配色 | 全中性灰（`#111` / `#F9F9F9` / `#FFF` / `#6B6B6B` / `#E5E5E5`） | 暮紫（v1.16.0 有意为之） |

「简洁漂亮」的来源是**克制**：三个圆角值、三档字号、零彩色堆叠。

本轮只动最有把握、风险最低的一项：
- 设置页所有卡 `18.dp → 12.dp`（9 处）—— 18 偏圆润可爱，12 偏克制现代；
- 详情页内部原本混着 `8` 和 `4` → 统一为 `10`（图标块）/ `6`（小元件）。

**没动的（需要用户口味）**：字号从 11 档压到 3 档、配色去紫。
配色是 v1.16.0 用户自己指定的暮紫主题，**不擅自改**；字号收敛影响面大且审美主观，等确认。
