# v1.8.6 — 拔掉章节清单阶段的最后两根刺（真机日志驱动）

> 承接 v1.8.5。装上 v1.8.5 后实测已从 52 KB/s 提到 350~660 KB/s，
> 但真机日志暴露出**两个新的确定性缺陷**，本版修掉。

## 证据：v1.8.5 的真机日志

```
21:13:38 并发设置：同时 2 本 × 每本 6 图（总 12 并发）
21:13:44 整本重下：1465752（图片解扰版本 0 < 53）
21:14:13 W 下载停滞 30148ms（1465752, bytes=0），自动续下     ← 又被误杀
21:14:21 W 下载停滞 33137ms（1252411, bytes=7284562），自动续下
21:14:38 章节清单：43 章并发拉取完成，耗时 55502ms（缓存命中 0 章）  ← 55.5 秒！
21:14:53 W 下载停滞 31114ms（1465752, bytes=0），自动续下
```

## 缺陷 1：章节清单拉取耗时 55 秒，仍被停滞判据误杀

`STALL_RESET_MS` 是 30 秒，而 43 章的清单要拉 **55.5 秒**。

而且 **清单拉取阶段一张图都不下、一个字节都不产生** ——
「几十秒零字节增长」在这一阶段是**完全正常的状态**。
所以判据「只看字节数」在这里必然误判 → 取消 → 重下 → 又 55 秒，来回死循环。

### 修法 A：现代本子**跳过** `/chapter_view_template`

读 `ImageScrambler.getNum` 的分支可以证明：

```python
if aid < scramble_id:        return 0
elif aid < 268850:           return 10
else:
    x = aid >= 421926 ? 8 : 10
    num = ord(md5(f"{aid}{name}")[-1]) % x * 2 + 2      # ← 公式里没有 scramble_id
```

即 **`aid >= 268850` 时，结果与 `scramble_id` 完全无关**
（现代本子的 aid 都在百万级）。而 `chapterDetail` 在 `scramble_id` 缺失时
**每章**都要额外打一次 `/chapter_view_template` —— 43 章就是 43 次无用 HTTP 往返。

新增 `ImageScrambler.scrambleIrrelevant(aid)`，在 `chapterDetail(photoId, albumId)` 里
命中该条件时直接用兜底值，**省掉一半请求**。

### 修法 B：清单阶段也上报「活动」

下载器新增 `touchProgress(albumId)`：每拉完一章就更新进度文件 mtime。
`DownloadManager` 的活动判据从「只看字节数」改为「**字节数变化 or mtime 变化**」。

安全性：touch 绑定在「真有一章拉回来了」上 ——
网络真挂起时一章也拿不到，mtime 不动，照样能判出卡死。

### 修法 C：并发 6 → 8，阈值 30s → 60s

真机实测单次 `/chapter` 要 4~8 秒（接口本身慢）。
并发提到 8 + 跳过一半请求，清单阶段 ≈ 降到原来的 1/3。

## 缺陷 2：心跳日志「最需要它的时候不打」

v1.8.5 的心跳放在 `if (got > 0L)` 里 ——
于是**图片普遍很慢、几十秒一张都没完成**的场景（正是最需要观测的时候）一条日志都没有。
移到 `got > 0` 外面：只要还在跑，每 30 秒必有一条。

## 剩余瓶颈：不是代码

切换到次优域名后瞬时也只有 18~67 KB/s，而同一台设备在 21:11 曾跑到 **624 KB/s**。
对照系统状态栏网速（0.10 KB/s ↔ 1.4 MB/s）可知：
**当前是用户网络/CDN 本身在波动**，代码侧已没有可摘的果子。
`markDomainSlow` 已能在这种波动下自动挑更快的 CDN。

## 发现的遗留问题（本版未修）

```
21:28:14 W 章节落库跳过：无任何章节目录（1477121）
```

`DownloadManager.kt:360` 用 `metaChapters`（来自 `/album` 的 `series`）来登记章节，
而**单行本的 `series` 本来就是空的** → 章节表里一条都不写。
虽然目录 `<root>/1477121/001/` 确实存在、书也下载成功了，
但**单行本的离线章节列表可能是空的**。

修法（下版）：单行本时将 `metaChapters` 兜底为
`listOf(Chapter(id = albumId, sort = 1, name = 书名))`，与下载器
「series 为空 → 按单章处理」的处理保持一致。
