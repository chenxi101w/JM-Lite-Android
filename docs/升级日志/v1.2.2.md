# JM 轻量版 v1.2.2 升级日志

**版本号**：versionName 1.2.2 / versionCode 17
**日期**：2026-10-01
**DB**：沿用 v13（无 schema 变更）
**包名**：`com.example.jmreader`

## 版本说明

用户反馈「漫画详细页的搜索功能」不可用。排查发现**不是功能被删了，而是它一直是坏的** ——
详情页点「作者」/「标签」搜索**没有任何反应**。本次修复，并补上标题的搜索入口。

---

## 一、根因：Kotlin 侧把搜索关键词丢弃了

详情页点作者 → `nav.navigate(Routes.search(b.author, "author"))`，路由正确带上了
query 与 mode。问题出在**接收端把 query 扔掉了**：

```kotlin
// DiscoverScreen.kt —— 非 keyword 模式一律传 null
initialQuery = if (initialMode == "keyword") initialQuery else null
```

```kotlin
// SearchScreen.kt —— 又加了一道 mode 判断
if (!initialQuery.isNullOrBlank() && initialMode == "keyword") { …发起搜索… }
```

**两道门叠加的后果**：点作者（`mode="author"`）→ query 在两处先后被丢弃 → **什么都没发生**。
点标签（`mode="tags"`）同理。

### 为什么之前"看起来修过"

Python 侧 `jm_bridge.py` 里有一段 v6.0.22 的修复注释：

> tags 模式的搜索词走 tagsJson（不是 keyword），keyword 本就为空。
> 原写法对空 keyword 一律 return，导致「按标签搜索」从未真正发起网络请求。

那次**只修了 Python 侧的空值拦截**，而 Kotlin 侧丢弃 query 的问题一直还在 ——
所以标签搜索依然点不动。**典型的"修了一层、另一层还堵着"**。

### 后端其实一直支持

`jm_bridge.py` 的 `search()` 完整实现了四种模式：

| mode | 实现 |
|---|---|
| `keyword` | 关键词搜索 |
| `author` | `search_author(search_query=kw, …)`，带精确匹配优先、模糊兜底的排序 |
| `tags` | 多标签并行抓取去重；**`tagsJson` 为空时自动回退用 `kw`**（`… or [kw]`） |
| `jmid` | 按 JM 号取单本详情 |

也就是说：**只要把 query 传下去就能用**，无需额外构造 `tagsJson`。

---

## 二、修复

1. **`DiscoverScreen.kt`** —— 不再按 mode 丢弃：
   ```kotlin
   initialQuery = initialQuery      // 原：if (initialMode == "keyword") … else null
   ```
2. **`SearchScreen.kt`** —— 不再限制 keyword，按传入 mode 原样搜索：
   ```kotlin
   if (!initialQuery.isNullOrBlank()) {
       vm.setKeyword(initialQuery); vm.onSearch()
       gridState.requestScrollToItem(0)
       vm.search(initialQuery, initialMode)   // 原：写死 "keyword"
   }
   ```
3. **`DetailScreen.kt`** —— 标题旁**新增搜索入口**（此前只有作者、标签能搜，标题没有入口）：
   标题行右侧加一个 18dp 搜索图标，点击后 `Routes.search(b.title, "keyword")` 按标题搜索。

修复后详情页三个搜索入口全部可用：

| 入口 | 触发 | mode |
|---|---|---|
| **标题**（新增） | 点标题旁搜索图标 | `keyword` |
| **作者** | 点作者名 | `author` |
| **标签** | 切到「搜索模式」后点标签 | `tags` |

> 注：API 直连搜索仍只用于 `keyword`（见 `JmRepository` 中的条件判断），
> author / tags 走 Python 链路 —— 这是既有设计，本次未改动。
