# v1.8.5 — 修正 v1.8.4 造成的下载变慢（回退过激的性能调优）

> 用户反馈：装 v1.8.4 后「下载比之前差多了」。
> 复核确认：v1.8.4 里**两处是明确的回退**，另有几处参数调得过于激进。

## 教训先说

v1.8.4 我把「性能调优」和「逻辑修正」混在一版里一起发了。
其中：
- **逻辑修正**（章节清单并发、全局并发池、domain 兜底）是**确定的改进**，保留；
- **性能调优**（解扰限流、超时缩短、连接池 keep-alive、慢域名切换）是**凭推断做的预防性改动**，
  没有真机数据支撑 —— 结果反而把速度做慢了。

**以后这类"预防性调优"必须单独一版、且默认取保守值，不能和修 bug 混在一起发。**

## 回退 1（严重）：解扰闸门把整条流水线压窄了

v1.8.4 的结构是：

```kotlin
async(Dispatchers.IO) {
    sem.acquire()                       // 图片并发位
    try {
        val got = downloadOne(...)      // 里面包含：网络取图 + 解扰 + 写盘
    } finally { sem.release() }         // ← 整段才释放
}
```

而 `downloadOne` 内部的解扰受 `descrambleSem(3)` 限流。于是：

- 解扰（每张几百毫秒 CPU）期间**一直占着图片并发位**；
- 解扰只有 3 个名额 → **有效并发被压到 3**；
- 吞吐 = 3 / (网络时间 + 解扰时间)，比原来 12 路全并发**低 4 倍以上**。

**修法**：把 `downloadOne` 拆成两段，网络位只覆盖真正的网络请求：

```kotlin
async(Dispatchers.IO) {
    // 阶段①：网络取图 —— 占图片并发位，取回后立刻归还
    sem.acquire()
    try { raw = fetchRaw(...) } finally { sem.release() }   // ★ 关键

    // 阶段②：解扰 + 写盘 —— 只受 descrambleSem 约束，不占网络位
    writeImage(...)
}
```

同时 `DESCRAMBLE_CONCURRENCY` 3 → **6**（与常见 8 核 SoC 的解码并行度匹配；
完全不限流会有内存压力，6 是折中）。

## 回退 2（严重）：慢域名判定传了空字符串 → 每 15 秒无条件换域名

v1.8.4 我把 `JmApiClient.chapterDetail` 的 `domain` 兜底去掉了（这是对的），
但 `markDomainSlow(domain)` 里传的仍是 `job.domain` —— 它**现在是空串**：

```kotlin
val idx = JmApiClient.IMAGE_DOMAINS.indexOf("")   // = -1
val next = (if (idx >= 0) idx else goodDomainIndex) + 1   // 永远走这里 → 一直往后推
```

结果：**每 15 秒无条件切一个 CDN 域名** → 连接池反复重建、每次都要重新 TCP + TLS 握手
（2~3 个 RTT），越"优化"越慢。

**修法**：
- `fetchRaw()` 返回实际成功的域名（`Pair<ByteArray, String>`），`writeImage` 用它做判定；
- `markDomainSlow` 里 `indexOf` 得到 -1 就**什么都不做**；
- 阈值 `SLOW_IMAGE_MS` 5s → **15s**，冷却 15s → **120s**（弱网下不再频繁轮换）。

## 回退 3：readTimeout 缩到 30s（弱网负优化）

v1.8.4 想把超时缩短以便"更早回收并发位"。但 CDN 抖动时单张图读到 30 秒以上很常见，
一超时就要换域名重下整张 → 更慢。改回 **60s**。

## 回退 4：连接池 keep-alive 1 分钟

v1.8.4 设 `ConnectionPool(16, 1, MINUTES)`。章节间隙/重试退避稍长就会把空闲连接全丢掉。
改回 OkHttp 默认的 **5 分钟**。

## 附带修正

`failures` 从非同步 `ArrayList` 改为 `ConcurrentLinkedQueue` ——
12 路并发写 `+=` 属于未定义行为，可能丢项或抛异常（v1.7.2 起就存在的老问题）。

## 保留（确认正确的 v1.8.4 改动）

| 改动 | 为什么保留 |
|---|---|
| 章节清单**并发**拉取（6 路） | 消除 9~18 秒的串行预热，是纯收益 |
| `chapterDetailCache`（TTL 10 分钟） | 续传/重下不再重复付预热成本 |
| 整本**统一并发池**（消除章间 straggler） | 慢图只拖累自己那一路 |
| `data_original_domain` 空值不再兜底 | 让 `goodDomainIndex`（记住上次成功域名）真正生效 |
| OkHttp `Dispatcher` per-host 5 → 16 | 默认 5 是隐形天花板 |
| `STALL_RESET_MS` 10s → 30s | 避免预热期被误判卡死 |
