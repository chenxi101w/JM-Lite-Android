# v1.9.0 — 修一个藏了很久的严重 bug：多章漫画解扰错位

> 用户报告：「**多章的漫画第一张下载没问题，但从第二章开始就会崩坏 — 多张漫画叠在一起**」。

## 根因：`num` 的 `aid` 参数传错了对象

解扰要用的 `num` 由三个东西决定：`(scramble_id, aid, 文件名stem)`。

jmcomic 官方（`jm_toolkit.py`）：

```python
@classmethod
def get_num_by_url(cls, scramble_id, url) -> int:
    return cls.get_num(
        scramble_id,
        aid=JmcomicText.parse_to_jm_id(url),   # ← aid 从图片 URL 里解析
        filename=of_file_name(url, True),
    )
```

而 `parse_to_jm_id` 的正则（`jm_toolkit.py:12`）：

```python
pattern_jm_pa_id = [
    (compile(r'(photos?|albums?)/(\d+)'), 2),   # ← 取第 2 组
    (compile(r'id=(\d+)'), 1),
]
```

图片 URL 长这样：

```
https://cdn-msp.jmapiproxy1.cc/media/photos/{photo_id}/00001.webp
                                       ^^^^^^^^^
                                       正则取的就是这个 —— photo_id（章节资源 ID）
```

**但我们传的是 `albumId`**：

```kotlin
val num = ImageScrambler.getNum(scrambleId, albumId, name)   // ❌
```

## 为什么一直没被发现

**因为单行本两者恰好相等。**

单行本的代码是 `ChapterRefOf(albumId, 1, ...)` —— `albumId == photoId`，所以算出来的
`num` 正好是对的。而 v1.8.2 那次「md5 带了扩展名导致 num 全错」的修复，
**也是用单行本校准的**（样本 `1477121/00001`、`1252411/00002`）。

也就是说：**单行本的正确表现，正好掩盖了多章路径上的错误**。
直到你下了一本 119 章的书。

多章时 `albumId != photoId` → `md5(f"{aid}{stem}")` 的输入就变了
→ `num` 算错 → 条带数不对 → `ImageScrambler.decode` 按错误的条带数重排
→ 图片横向错位 → 视觉上就是「多张画叠在一起」。

## 改动

| 文件 | 改动 |
|---|---|
| `NativeAlbumDownloader` | `writeImage()` 参数 `albumId: Int` → **`photoId: Int`**；调用处传 `job.photoId`；verbose 日志 `aid=` → `photo=` |
| `ImageScrambler` | `ALGO_VERSION` **53 → 54** |
| `DownloadManager` | `healLegacyImages()` 新增「**只重下多章**」判断（章节目录数 > 1） |

### 为什么必须提 `ALGO_VERSION`

v53 及更早版本下的错图**内容是合法的 JPEG**（只是内容错位），
所以 `isStaleBrokenFile()` 识别不出来 —— 它只认「`.webp` 扩展名却是 JPEG 内容」，
那是 v1.6.6 时代的另一种坏法。

**只能靠版本号升级触发整本重下**。

### 为什么只重下多章

单行本的 `num` 本来就算对，让它跟着重下是纯浪费流量 —— 你手机上 26 本全是单行本、
共 852 MB。加一句章节目录数判断就省掉了这笔账。

## 现场情况

- 手机现有 **26 本全是单行本**（章数 = 1）→ **本次修复对它们零代价**
- 那本 876 MB / 119 章的 `357680` 已经不在了（估计是崩坏后手动删的）

## 怎么验证

1. 装上 v1.9.0
2. 下一本**多章**的漫画
3. 打开看**第二章及以后**是否正常

装上后 App 启动时不会触发大重下（你那 26 本单行本会被跳过），
所以可以放心立刻装。

## 教训

**用单行本校准算法 = 只覆盖了单行本的路径。**
凡是分「单本 / 多章」两条代码路径的功能，必须两条都验证。
这次的错误是被"单行本恰好正确"长期掩盖的。
