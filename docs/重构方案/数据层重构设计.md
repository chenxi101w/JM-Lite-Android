# JM 轻量版 · 数据层重构设计 v2（单表方案，v1.12.0）

> 变更：应用户「1234 全做 + 能合并的合并 + 省空间（单章漫画）」要求，由三表方案升级为
> **books + comic_status + read_progress 三表合一 → `comics` 单表**；
> chapters 表只存多章漫画，**单章漫画不入章节表**（photoId≡bookId）。
> 状态：**已确认开工**，阶段 A→B→C→D，每阶段编译装机验证。

---

## 一、新数据模型（2 张表）

### comics（唯一主表：一行 = 一本看过的漫画）

```
id             INTEGER PRIMARY KEY  -- JM 号
title/author/coverUrl/tags/description/pageCount   -- 元数据快照（唯一副本，不再双存）
localDir       TEXT    本地目录，空 = 不在本地（原 books.savedDir 改名）
addedAt        INTEGER 加入时间
cached         INTEGER 0/1 智能缓存标记
finished       INTEGER 0/1 已看完（没看完的 = 剩下的，无需标记）
favorite       INTEGER 0/1 收藏
blocked        INTEGER 0/1 拉黑
viewCount      INTEGER 打开阅读器次数（唯一副本）
lastReadAt     INTEGER 最后阅读时间 ms
lastChapterId  INTEGER 最后读到的章节（原 read_progress.chapterId）
lastPageIndex  INTEGER 最后读到的页（原 read_progress.pageIndex）
索引：localDir（书架高频过滤）
```

- **删本地 = 清 localDir（行保留）**——账本永不丢历史，这正是「看过的」语义。
- Book Kotlin 类**原位改造**（字段名 finished/favorite/viewCount 不变，语义本来就是它），
  改名列 savedDir→localDir 用 @ColumnInfo；UI 拿到的还是 Book 对象，**界面零改动**。

### chapters（章节清单）—— 只存多章

- **单章漫画不建行**：JM 单行本 photoId≡bookId，阅读器路由直接用真实 chapterId（内存传递），
  账本 lastChapterId 记真实值；省 N 行存储 + 结构少一态。
- 多章漫画章节清单照旧（翻章/读完标记需要）。
- 章节 finished 保留（账本 finished 的推导依据：多章全读完 → 整本看完）。

### 取消的表/列

| 取消 | 去向 |
|---|---|
| comic_status 表（位掩码 8 位） | finished/favorite/blocked 三列 + PUSH_MASK 整个删除 |
| read_progress 表 | lastChapterId/lastPageIndex/lastReadAt 三列 |
| books.downloadedEver | DROP（legacy） |
| books.finished/favorite/viewCount 双写 | 字段保留但**唯一写入点**（不再有账本副本冲突） |

其余表（downloads / system_config / blacklists / blocks / aliases / categories /
comic_categories / search_history / subscriptions / sub_updates / tag_library / tag_library_exp）本轮不动。

## 二、数据链路规则（唯一写入点，收敛在 ComicLedger）

| # | 事件 | 动作 |
|---|---|---|
| 1 | 打开阅读器 | 行 upsert：viewCount+1、lastReadAt、lastChapterId/PageIndex、快照补全 |
| 2 | 标看完（读末尾/手动） | finished=1 |
| 3 | 收藏/取消 | favorite 1↔0 |
| 4 | 拉黑/取消 | blocked 1↔0（blacklists 表仍存作者级明细） |
| 5 | 下载完成 | localDir 填上（行不存在则建，finished=0） |
| 6 | 删除本地 | **清 localDir**（行保留）+ 删文件 + 删 chapters 行 |
| 7 | 派生视图 | 书架 = localDir<>''；「已删可重下」= localDir='' 的行；搜索已下载判断 = localDir<>'' |
| 8 | 云同步 | push = comics 全表 id（**看过即账本，无掩码筛选**）；pull = 建空行（localDir=''） |

启动体检 auditDataOnLaunch 退役（单源无双写，无漂移可补）。

## 三、一次性数据修复（MIGRATION_13_14，自动执行）

目标行集 = 旧 comic_status 实质号（status & 0xF ≠ 0，61 本）∪ books 现行（26）∪ read_progress（23，补建）≈ 61~64 行：

1. `comics` 建新表 → INSERT SELECT 三表合并：
   - 元数据：books 为准，账本快照补空
   - finished/favorite/blocked：**位换算成列**（BIT_FINISHED=2 / BIT_FAVORITE=8 / BIT_BLOCKED=16），
     与 books 旧列取 MAX（账本为准的修复原则：只置位不误删）
   - viewCount = MAX(books.viewCount, 旧账本.viewCount)；lastReadAt = MAX
   - localDir = books.savedDir；cached/addedAt 随 books
   - lastChapterId/PageIndex 从 read_progress 并入（无账本行的 online 阅读补建行）
2. DROP books / comic_status / read_progress → RENAME comics→生效（表重建模式，
   不依赖 SQLite DROP COLUMN，minSdk24 老设备安全）
3. **升级前 adb 备份 jmcomic.db**，迁移后 run-as 核对行数
