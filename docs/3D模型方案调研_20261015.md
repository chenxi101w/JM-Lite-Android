# 3D 图标方案调研（2026-10-15）

> 需求原话：「我想要一个特别精致的 3D 模型，**双面都要**，然后动画是**慢速旋转带细节反光**
> 而不是你这种全局反光，你看看网上有哪些资料」。

---

## 一、先把「人家」的模型拆开看（一手数据，非推测）

下载了参考项目 `1976764/jm-comic-android` 的 `assets/models/JM.glb`（435,876 字节）并逐字段解析：

| 项 | 实测值 |
|---|---|
| 导出器 | **`THREE.GLTFExporter r180`** → 用 three.js 导出 |
| 网格 | 1 个 mesh / 1 个 node / **4528 三角面**（13,584 顶点，**无索引**，硬边直出） |
| 顶点属性 | `POSITION` / `NORMAL` / `TEXCOORD_0`（有 UV 但**没有贴图**） |
| 贴图 | **0 张**（`textures: 0`、`images: 0`） |
| 材质 | `metallic = 1.0`、`roughness = 0.12`、`baseColorFactor = [0.63, 0.63, 0.63]`（中灰）<br>`doubleSided = false`、无法线贴图 / 无 AO / 无自发光 |
| 动画 | **0 个**（旋转是 HTML 的 `auto-rotate` 做的，不是模型自带） |
| 包围盒 | X 跨度 2.630 / Y 跨度 1.561 / **Z 跨度 0.100** → 一块很扁的浮雕板 |
| Z 分布 | **前后完全对称**：最外层各 3876 个顶点，前侧 2102 面 / 后侧 2102 面 |

**三条结论（直接决定我们该怎么做）：**

1. **「锃亮」不是画出来的，是金属材质 + 环境贴图反射**。`metallic=1, roughness=0.12`
   配一个 IBL 环境 → 每个面因为法线朝向不同，反射到环境里不同的位置，
   于是**曲率大的地方反射变化快、平面处反射稳定** —— 这就是「细节反光」。
   我上一版手绘一条白色高光带扫过去，是「全局反光」，**方向错了，不可能做出那个效果**。
2. **它本来就是双面的**：Z 分布对称 = 正反两面同样鼓起来（像一枚压铸的纪念币/贴纸），
   所以转到背面不空。这正面回答了「双面都要」。
3. **没有贴图**，说明它是**纯几何造型**（中灰金属），不是把位图贴上去。
   对我们的彩色图标，要么保留颜色（低金属度 + 低粗糙度 = 亮面搪瓷），
   要么做「金属化」处理（丢颜色换质感）。

## 二、建模路线（去哪儿做这个模型）

### A. Blender 无头脚本（`bpy`）—— 保真度最高，推荐

**可行性已确认**：`pip install bpy` 能装，但**必须严格匹配 Python 版本**
（bpy 4.0→Py3.10 / **4.1–4.5、5.0→Py3.11** / 5.1→Py3.13）。我们公共测试环境正好是 **Python 3.11.16**，
可以直接装 Blender 4.x（建议 **4.5 LTS**，维护到 2027）。

**关键配方（这是做到「精致 + 细节反光」的核心）**：
- **Bevel 修改器**：角度限制 30–40°，1–2 段 → 机加工感的倒角（3–4 段偏软塑料感）；
- **Weighted Normal 修改器**：`keep_sharp=True`，放在最后 → 大平面保持绝对平整、
  只有倒角处挂高光。**这两个加起来就是「金属质感」的标准打法**（否则面会糊成一片）；
- 导出：`bpy.ops.export_scene.gltf(filepath=..., export_format='GLB', export_apply=True)`
  （`export_apply=True` 让修改器在导出时烘焙）；
- CI 用法：`blender -b -P script.py`，加 `--factory-startup`、`--python-exit-code 1`
  （否则 Python 报错仍可能退出码 0，CI 静默通过）；
- **坑**：① 4.0 起 `import_scene.obj` 已移除，要用 `wm.obj_import`；
  ② GLB 导出**不是字节可复现**的，别拿 byte-diff 做 CI 断言；
  ③ `bpy` 包体积极大（内置整个 Blender），平台相关。

**我们能做出来的「精致」形态**（这是 bpy 的价值所在，AI 生成做不到）：
把图标**按图层拆开**（外框 / 放射线 / 书本 / 爱心 / 闪电 / 气泡…），
每层用各自 alpha 蒙版生成网格、给不同 Z 深度与倒角，再叠成一个浮雕组 →
旋转时能看到**层与层之间的视差**，这才是「精致」；
背面单独设计一层（浮雕 logo / 纹理），旋转过去不空白。

### B. 本地多视图图生 3D + PBR —— 最快拿到「真 3D 物体」

本机就有这个能力（`buddy-multimodal-generation` 技能）：

| 能力 | 用法 |
|---|---|
| 图生 3D | `3d --image-url <图>` |
| **多视图生 3D** | `--multi-view JSON`，可提供 **left / right / back / top / bottom / 斜前视图** |
| PBR 材质 | `--enable-pbr` |
| 面数控制 | `--generate-type Normal / LowPoly / Geometry / Sketch` |
| 输出 | 默认 **OBJ + GLB**（可加 STL/USDZ/FBX） |
| 耗时 | 1–5 分钟 |

**「双面都要」在这里的解法**：用 `--multi-view` 喂一张**我们自己设计的背面图**
（例如把图标做成压印/烫金图案），模型就会按背面图去生成背面几何，而不是"猜"。

⚠️ 风险：单图生成时**背面是模型用先验外推的**（网上多篇 2026 对比都这么说：
「背面未被拍摄时会被合理编造」）；扁平卡通插画转 3D **容易丢细节**（用户已因此否过一版）。

### C. three.js + GLTFExporter（人家的原路线）

Node 里写几何代码导出 GLB。我们沙箱有 Node 22。
相比 bpy 没有优势（写几何比 bpy 的修改器栈麻烦），仅作「与人家的路线一致」记录。

### D. 线上 AI 图生 3D 服务（对比结论）

| 服务 | 强项 | 备注 |
|---|---|---|
| **Hunyuan3D 3.1**（腾讯） | 几何+贴图最均衡、便宜、快、支持多视图 | 2026 多篇对比的默认推荐 |
| **TRELLIS 2**（微软，MIT 开源） | 保真度最好、支持 4K 贴图、开放面/薄片表现好 | 可本地跑（需 16–24GB 显存） |
| **Tripo v3.1** | 最快、quad 拓扑、贴图对齐输入图 | 适合 hero asset |
| **Meshy 6** | 硬表面/机械件最强、支持多图输入 | 有 remesh/retexture 工具链 |
| **Rodin 2.0** | 几何保真、可出 STL | 3D 打印友好 |

共同点：**都出 GLB**、都能带 PBR 贴图；**背面都是外推的**（要背面就得给多视图）。

## 三、App 内渲染路线（怎么把它转起来 + 反光）

### A. WebView + `<model-viewer>`（人家的路线）

贴一下人家 `assets/about_model.html` 的关键属性：

```html
<model-viewer src="models/JM.glb" auto-rotate rotation-per-second="20deg"
              disable-zoom interaction-prompt="none"
              shadow-intensity="0" exposure="1.2"
              camera-orbit="0deg 95deg 200%"></model-viewer>
```

**「细节反光」在这里调什么**（官方文档实锤）：

| 属性 | 作用 | 我们的取值建议 |
|---|---|---|
| `environment-image` | **控制模型的环境反射**（不影响背景）。可填 `neutral` / `legacy` / 或 .hdr/.jpg 的 URL；不填则用默认中性环境 | 先用内置 `neutral`（**零体积**）；想要更「影棚」就放一张小 HDR |
| `skybox-image` | 同时设背景 + 当环境贴图 | 我们不需要背景（透明），只用 `environment-image` |
| `exposure` | 曝光（HDR 环境时用） | 1.0–1.3 |
| `tone-mapping` | `neutral`(默认) / `aces` / `agx` / `reinhard` / `linear` / `none` | 金属高光想要更戏剧化用 `aces`/`agx`；想色彩准用 `neutral` |
| `shadow-intensity` / `shadow-softness` | 阴影浓度 / 软度 | 0（人家就是 0）或 0.2 |
| `rotation-per-second` | 自动旋转角速度 | **20deg**（对齐人家 = 18 秒一圈） |

**环境图分辨率提示**：内部会固定压到 1024×512，**超过 1k 没意义** →
可以只放一张很小的 equirect jpg 当环境，体积可控。

体积代价：`model-viewer.min.js` 约 **1MB 级** + GLB（我们预计几十~几百 KB）。

### B. SceneView（Compose 原生 + Google Filament）

- 依赖：`implementation("io.github.sceneview:sceneview:4.56.0")`，Compose 声明式：
  `rememberEngine()` / `rememberModelLoader()` / `rememberModelInstance(...)` → `ModelNode(autoAnimate = true)`；
- 支持 HDR 环境：`environmentLoader.createHDREnvironment("environments/sky_2k.hdr")`；
- 不用 WebView，启动更快、无 JS 运行时；
- **代价**：Filament 会带原生 `.so`，通常**每个 ABI 好几 MB**，对我们这个 20MB 的包更重
  （2K HDR 本身也 5–10MB，得换小尺寸或程序化生成环境）。

**结论：论体积，`model-viewer` + WebView 反而比 Filament 原生更轻**，而且与人家的观感 100% 一致。

## 四、环境贴图（反射的来源）从哪来

| 来源 | 说明 |
|---|---|
| model-viewer 内置 `neutral` | **零体积**，PBR 中性环境，够用 |
| https://polyhaven.com/hdris | 免费 CC0 HDRI，但 2K HDR 常有 5–10MB → 需降采样成 1k jpg |

| 自制 equirect jpg | ≤1024×512 即可；自己画一个「影棚布光」渐变也能出好看的金属反射 |

## 五、推荐方案与代价

| 方案 | 建模 | 渲染 | 体积 | 观感上限 | 我的评价 |
|---|---|---|---|---|---|
| **① bpy 程序建模（分层浮雕 + 双面）+ model-viewer** | Blender 4.5 LTS 无头脚本 | WebView + model-viewer | **+约 1.1–1.5MB** | ★★★★★ 细节 100% 可控、可做多图层视差 | **推荐**：唯一能同时做到「精致」「双面」「细节反光」且不丢图标细节 |
| ② 本地多视图图生 3D（PBR）+ model-viewer | 技能生成（1–5 分钟） | 同上 | +1.1MB ~ +3MB | ★★★☆ | 最快；但细节靠模型发挥，可能要试几次 |
| ③ SceneView 原生渲染 | 任选 | Filament | **+3–6MB（原生库）** | ★★★★ | 只有当「不想用 WebView」时才值 |
| ④ 维持现状（平面位图旋转） | — | Compose | 0 | ★★ | 转侧面会露馅（压成一条线），永远达不到 |

**关键取舍**：①/② 都要 **+1MB 以上**，而我们刚连着 5 个版本在砍体积。
这是一个明确的方向取舍，需要用户拍板 —— 建议只把 3D 展示放在**关于页**
（一个页面），其余保持轻量。
